A guide · a non-QA example

A résumé-builder agent

Nothing here is QA-specific. It's a small Claude Code agent that keeps a résumé in Markdown, tailors it to a job description, scores it for ATS, and renders a polished Word document — the "build your own agent" pattern applied to something everyone needs.

What it is: three small parts

The whole agent is a tiny Claude Code project — no servers, no framework. Three files carry all of it:

.claude/CLAUDE.md
The rules. It encodes the résumé's format (sections, order, bullet style, length) and an ATS scoring rubric Claude uses to grade every draft. Claude reads this file automatically at the start of each session.
résumé.md
The Markdown résumé — the version-controlled source of truth. Every tailored variant is a diff you can review, revert, or branch, exactly like code.
generate-docx.js
The renderer. A small Node script that turns the Markdown into a styled .docx using the docx npm library — headings, accent rules, a skills table, clickable links.

The rules (.claude/CLAUDE.md)

There's no configuration language and no plugin API — the agent's entire behavior is just a context file. Claude Code reads CLAUDE.md automatically every session, so whatever you write there becomes the standing instructions for every tailoring pass and every score. Here's a generic version:

# Résumé project context

## Owner
- Name: Your Name
- Email: you@example.com
- Location: City, ST

## Format rules
- Source of truth: Markdown (.md), version-controlled; render to DOCX/PDF
- Length: 2–3 pages max
- Sections, in order: Summary, Selected Highlights (5 bullets),
  Core Skills (table), Professional Experience, Education & Certifications
- Bullets: start with a strong action verb; quantify impact; 1–2 lines each
- No objective statement, no references section

The ATS scoring rubric

The same file defines how drafts get graded. When you ask "score this against the rubric," Claude walks these five weighted checks and reports a percentage with concrete gaps:

Keyword match — 40%
Are the job description's keywords actually present in the résumé — tools, titles, and domain terms the applicant tracking system will scan for?
Format compliance — 15%
No tables, images, or odd headers that ATS parsers choke on. Markdown as the source keeps the structure clean by construction.
Section headers — 10%
Standard names ATS software recognizes: Summary, Experience, Skills, Education — not clever synonyms.
Quantified achievements — 15%
Numbers and percentages in the bullets — measurable impact rather than lists of duties.
Relevance — 20%
Do the bullets actually align to this job description, or is it the same generic résumé every posting gets?

The workflow: tailor → score → render

One session, three moves. Everything happens in the terminal, and every change lands as an editable diff to résumé.md.

  1. Tailor to the job description
    > Tailor résumé.md to this JD, keep it truthful, then score it
  against the ATS rubric.

  [paste the job description]
    WhyClaude rewrites the Markdown to surface your most relevant experience and mirror the JD's language — reordering highlights, swapping which skills lead — while staying strictly truthful. Nothing is invented; the raw material is your existing résumé.
  2. Score ATS readiness
    WhyClaude grades the tailored draft against the five weighted rubric checks in CLAUDE.md and lists concrete gaps to close — "the JD says 'stakeholder management' four times and your draft never does", "the certifications section header won't be recognized". You fix, it re-scores.
  3. Render the Word document
    node generate-docx.js
    WhyThe script reads the final Markdown and emits a styled .docx ready to attach to an application. The pretty file is disposable output; the Markdown stays the source of truth.

The renderer (generate-docx.js)

The renderer is deliberately boring: a single Node script that uses the docx npm library to build a Word document from the Markdown — section headings with an accent rule beneath them, a Core-Skills table, bullet lists, and clickable email and portfolio links. No LLM involved in this step; rendering is deterministic, so the same Markdown always yields the same document.

npm install docx
node generate-docx.js

Conceptually it's just the library's building blocks stacked up:

const doc = new Document({
  sections: [{ children: [
    new Paragraph({ text: "Your Name", heading: HeadingLevel.TITLE }),
    new Paragraph({ text: "Summary", heading: HeadingLevel.HEADING_1 }),
    // …bullets from the Markdown…
    new Table({ rows: skillRows }),   // Core Skills
  ]}],
});

Claude Code wrote this script in the first place — describe the styling you want, approve the steps, and keep the code like any other file in the repo.

A ready-to-run copy ships with this repo. A complete, generic version of this agent lives at docs/site/_examples/resume-agent/ — resume.md, .claude/CLAUDE.md (rules + ATS rubric), and generate-docx.js. Clone the repo, then cd docs/site/_examples/resume-agent && npm install && node generate-docx.js to render a sample resume.docx. Everything in it is a placeholder — replace it with your own.

Make it your own

This is just a Claude Code project. A .claude/CLAUDE.md with your format and rubric, a Markdown résumé, and a render script — that's the entire agent. Swap the rules for your own style (different sections, a stricter length cap, a different rubric weighting) and you have your own résumé agent. The pattern is the same one behind every agent in this catalog: encode the rules in context, keep the source in version control, let a small script handle the deterministic part.
