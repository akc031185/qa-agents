A guide · build it yourself

Build your own agent

Every agent in this catalog is just a small, focused program. With an AI coding CLI — Claude Code or OpenAI's Codex — you describe the agent you want, and it scaffolds, runs, and iterates on the code with you. This guide shows the whole path.

What you're building

Not a chatbot, and not a server. A scoped, single-purpose CLI: typed inputs in, structured outputs out, one job done well. It runs when you invoke it, prints or writes its result, and exits. Most of it is ordinary deterministic code — file reading, parsing, counting. If the job includes a judgment call ("what's the likely cause of this flake?"), the program can make one narrow LLM call for exactly that part, and nothing else.

That shape is what makes these agents cheap to build, easy to review, and safe to run in CI — and it's the shape every agent in this catalog follows.

Path A — Claude Code CLI

Claude Code is Anthropic's coding agent that lives in your terminal. You point it at a project, describe the tool you want, and it reads your code, scaffolds the program, installs dependencies, runs it, and fixes what breaks — showing you each step for approval. Full setup docs: code.claude.com — getting started.

Install it

  1. Install via npm (needs Node 18+)…
    npm install -g @anthropic-ai/claude-code
    WhyThe simplest route if you already have Node.js. One global package, updated with npm update -g.
  2. …or use the native installer (no Node required)
    # macOS / Linux / WSL
curl -fsSL https://claude.ai/install.sh | bash

# Windows PowerShell
irm https://claude.ai/install.ps1 | iex
    WhySelf-contained binary — handy on machines where you don't manage a Node toolchain.
  3. Verify
    claude --version
    WhyIf a version prints, you're installed. First run of claude will walk you through signing in.

Account: free vs paid

Claude Code runs on either a paid Claude plan (Pro or Max) — a fixed monthly subscription that covers CLI usage within the plan's limits — or an Anthropic API key, which is pay-as-you-go: you're billed per token the agent uses. Subscription = predictable monthly cost; API key = costs scale with how much you build.

The free Claude.ai plan is chat-only — it does not drive the CLI. There's no fully-free tier for Claude Code (or, as you'll see below, for Codex). To try it you need a paid plan or an API key. Check current plans & pricing → claude.com/pricing

Build one

  1. Start Claude Code inside your project
    cd your-project
claude
    WhyClaude reads the project it's launched in — your test setup, package manager, and conventions shape what it builds.
  2. Give it a real, scoped prompt
    > Build a small TypeScript CLI called flaky-finder that reads
  every JSON file in ./test-results, finds tests that both
  passed AND failed across runs, and writes a JSON report.
  Expose it as: npm run analyze -- --input ./test-results
  --output report.json
    WhyClaude scaffolds the files, installs deps, runs the tool against your data, and iterates — asking you to approve each file edit and command as it goes. The full prompt is in the worked example below.
  3. Own the result
    npm run analyze -- --input ./test-results --output report.json
git add -A && git commit -m "Add flaky-finder CLI"
    WhyThe output is a normal program in your repo — you read it, run it, commit it, and change it like any other code. No lock-in to the tool that wrote it.
Tip: add a CLAUDE.md. A short markdown file at the repo root ("we use pnpm, tests live in ./tests, prefer zod for validation") is read automatically on every session, so the agent starts with your project's context instead of rediscovering it.

Advanced: subagents & the Agent SDK

Once the basics click, Claude Code can define subagents — markdown files in .claude/agents/*.md that give a task its own prompt and tool permissions, which Claude delegates to automatically. And for running agents programmatically — say, your flaky-finder as a CI step with no human at the keyboard — the Claude Agent SDK (npm i @anthropic-ai/claude-agent-sdk or pip install claude-agent-sdk) exposes the same harness as a library, driven by an API key. Details: Agent SDK overview.

import { query } from "@anthropic-ai/claude-agent-sdk";

for await (const msg of query({
  prompt: "Analyze ./test-results and write report.json",
  options: { allowedTools: ["Read", "Glob", "Write"] },
})) { /* stream progress into your CI log */ }

Path B — OpenAI Codex CLI (the alternative)

If you're already in the ChatGPT ecosystem, Codex CLI is OpenAI's equivalent terminal coding agent, and the build flow is the same: launch it in your project, paste the same prompt, approve its steps as it scaffolds, runs, and iterates. Docs: developers.openai.com — Codex CLI.

  1. Install
    npm install -g @openai/codex
    WhySame npm-global pattern as Claude Code.
  2. Sign in — paid plan or API key
    codex   # first run prompts you to sign in
    WhyCodex runs on a paid ChatGPT plan or an OpenAI API key — mirroring Claude Code's model exactly. The free ChatGPT tier doesn't drive the CLI either.
  3. Build — same prompt, same loop
    cd your-project
codex
> Build a small TypeScript CLI called flaky-finder that…
    WhyDescribe the tool, approve the steps, keep the code it produces.
High-level differences, not a verdict: Codex uses OpenAI's models rather than Anthropic's, and out of the box it carries less project-level configuration and context convention than Claude Code's CLAUDE.md / subagent setup. Both will happily build the worked example below.

Worked example: a flaky-test finder

Here's the full prompt you'd hand to either CLI, word for word. Notice how it pins down inputs, outputs, the one optional LLM call, and the exact command surface — the more the prompt reads like a spec, the less the agent has to guess.

Build a small TypeScript CLI called flaky-finder.

- Read every JSON file in ./test-results — each file is one
  test run, listing test names with "passed" or "failed".
- Find tests that BOTH passed and failed across the runs
  (those are the flaky ones).
- Optionally, if an API key is present in the environment,
  make one LLM call per flaky test to classify the likely
  cause (timing, ordering, external dependency, …) and
  suggest a fix. Skip this cleanly if no key is set.
- Write the findings to a JSON report, sorted by fail rate.
- Expose it in package.json as:
    npm run analyze -- --input ./test-results --output report.json
- No servers, no watch mode: run once, write the file, exit
  non-zero if any flaky tests were found.

A few approved steps later, you get a report shaped like this:

{
  "runsAnalyzed": 12,
  "flakyTests": [
    {
      "name": "checkout › applies discount code",
      "passed": 9,
      "failed": 3,
      "failRate": 0.25,
      "likelyCause": "race condition — asserts before the cart total re-renders",
      "recommendation": "await the price update instead of a fixed 500ms sleep"
    },
    {
      "name": "search › returns paginated results",
      "passed": 11,
      "failed": 1,
      "failRate": 0.08,
      "likelyCause": "external dependency — live search index occasionally cold",
      "recommendation": "stub the search service in this suite"
    }
  ]
}
Note the split: counting passes and failures is plain code — free, instant, deterministic. Only likelyCause and recommendation came from the LLM, and the tool still works (minus those two fields) with no API key at all.

Free vs paid — the honest version

Good LLM usage costs money. The models that make these CLIs feel like a competent pair-programmer are the expensive ones to run, and neither vendor gives them away for terminal use. Budget for it the way you'd budget for any developer tool.
Subscription = fixed monthly cost. A paid Claude plan (Pro/Max) or paid ChatGPT plan is a flat fee with generous-but-real usage limits. Best when you'll use the CLI regularly — heavy weeks don't cost extra.
API key = pay per token. Building one small agent like the flaky-finder is genuinely cheap this way; costs scale with how much and how often you build. Best for occasional use, CI pipelines, and the Agent SDK.
The free chat tiers won't run either CLI. Free Claude.ai and free ChatGPT are chat-only. Plans and limits change — always check the live pages: claude.com/pricing and openai.com/chatgpt/pricing.

Which to pick

Both are capable; the fair answer is about fit, not quality.

Claude Code
Transparent step-by-step approval of every edit and command; CLAUDE.md for durable project context; subagents for splitting work; the Agent SDK when you want the same harness running headless in CI; MCP servers to plug in trackers, browsers, and databases. The deeper toolbox once agents become a habit.
OpenAI Codex CLI
The natural choice if your team already pays for ChatGPT — same sign-in, same ecosystem, and the identical describe → approve → own-the-code loop. Less project-config surface out of the box, which can also mean less to learn on day one.
Honestly?
Whichever one you can sign into today. The skill that transfers is writing scoped, spec-like prompts — the worked example above runs on either.
