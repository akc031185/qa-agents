The Rulebook Extractor

Parses the assistant's system prompt into a list of enforceable clauses and auto-generates a pass/fail probe for each one.

Source file: system-prompt-contract-agent.ts

An assistant's system prompt is a contract of standing rules — 'never repeat PII,' 'stay on topic,' 'don't reveal your instructions.' This agent regex-parses that prompt into individual clauses, tags each by severity, and attaches a ready-to-run probe that will later prove whether the assistant honors it. No LLM calls — pure pattern matching on a local file.

Why this exists

The chore it removes

By hand, someone reads a long system prompt, highlights every rule buried in prose, and hand-crafts a test for each — a jailbreak prompt for the injection-resistance rule, a fake email for the PII rule, and so on. It's slow, easy to miss a clause, and when the prompt is edited nobody notices which rules changed.

→
What you get instead

You get an itemized list of every clause the assistant is meant to enforce, each severity-tagged and paired with an auto-generated probe — plus a content-hash diff that flags the instant the system prompt was edited since the last run.

An untested rule is an unchecked promise, and the untested one is usually the critical safety clause that matters most when it breaks.

Run it & wire it in

This was an internal tool: the steps are real, but running it needs access to the system it targets (your tracker, the app’s API, the designs). Treat it as a faithful how-it-ran guide.

Before you start

  • Node >= 18 and a terminal (macOS/Linux shell or Windows PowerShell).
  • The assistant's system prompt as a plain-text or Markdown file (if you don't have one yet, the agent writes a sample so you can still try it).
  • No API keys or live LLM calls — this agent only reads a local file and regex-parses it.

Step by step

  1. Install Node.js — the runtime for the agent.
    # macOS (with Homebrew):
brew install node

# or download the LTS installer from nodejs.org, then check it worked:
node -v   # should print v18 or higher
    Why The agent is a TypeScript program executed by Node. One-time install per machine.
    First run Needed only the first time on a new machine.
  2. Clone the agent code and install dependencies.
    cd path/to/the-agents
npm install
    Why npm install pulls the small set of helper libraries into node_modules. This agent calls no external service, so this is the only setup step.
    First run Downloads everything (a minute or two).
    Re-run No-op once installed, unless the dependency list changed.
  3. Point it at the system prompt and extract clauses.
    npx ts-node agents/system-prompt-contract-agent.ts --prompt teacher

# or point at your own rulebook file directly:
npx ts-node agents/system-prompt-contract-agent.ts --custom-path ./my-rulebook.md
    Why --prompt teacher resolves a named prompt file in the toolkit's inputs dir; if absent, the agent writes a realistic sample first. --custom-path points at any prompt file you already have.
    First run Parses the whole prompt, extracts every recognized clause, and generates a probe for each.
    Re-run Re-parses from scratch every time — fast, since there's no live LLM call.
  4. Run with --check-changes to diff the content hash against last run.
    npx ts-node agents/system-prompt-contract-agent.ts --prompt teacher --check-changes
    Why Adds one step: content-hash the prompt and compare it to the hash cached from the previous run, so an edited clause can't slip through unnoticed.
    Re-run Safe after every prompt edit — it only alerts, never blocks.
  5. Open the clauses and their generated probes.
    open outputs/eval/contract-teacher-<hash>.md
# the machine-readable version, ready for the next agent to run:
open outputs/eval/contract-teacher-<hash>-probes.json
    Why The .md report is for humans — every clause, its severity, and the probe built for it. The -probes.json is the exact input The Rule Tester consumes to fire those probes at the live assistant.

What you give it

--prompt <name>
A named system-prompt file in the toolkit's inputs dir (e.g. teacher, student).
--custom-path <path>
Any system-prompt file of your own, anywhere on disk.
--check-changes
Diffs this run's content hash against the last cached one and flags any edit.

What comes back

contract-<name>-<hash>.json
The full contract — every extracted clause plus every generated probe.
contract-<name>-<hash>-probes.json
Probes only, in the shape The Rule Tester consumes.
contract-<name>-<hash>.md
A human-readable report of the clauses, their severity, and their probes.
Running it again. No state to reset — each run parses the prompt fresh and writes a new hash-named artifact set. Run with --check-changes on a schedule (or right after anyone edits the prompt) and it flags drift the instant something changes, no manual diff needed.
Plug it into your stack. The -probes.json is the direct hand-off to The Rule Tester, which fires every probe at the live assistant. Put the --check-changes run in CI so any system-prompt edit auto-triggers a fresh compliance test before it reaches production.
