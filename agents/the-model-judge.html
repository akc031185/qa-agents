Grading the AI assistant's answers

The Model Judge

Benchmarks multiple LLMs on one shared prompt set, scores each answer with an LLM-as-judge rubric, and ranks them to name a winner.

Source file: model-comparison-agent.ts

Any assistant can be backed by several candidate models, and they don't score equally. This agent runs one fixed prompt set through each model, scores every response on a shared rubric, and lays the results side by side so the model choice rests on evidence, not preference.

Why this exists

The chore it removes

Benchmarking models by hand means opening each one, pasting the same prompt, copying the answer into a spreadsheet, and repeating that across dozens of prompts and five or six models — then eyeballing accuracy, clarity, and hallucination with no consistent scale. It takes days, and one tired reviewer is not a reproducible scoreboard.

→
What you get instead

Every model answers every prompt automatically, each response is scored on the same rubric, and you get a ranked scoreboard with a named winner, a pass rate, and a recommendation — in one run.

The backing model decides whether the assistant ships accurate answers or confident hallucinations, so the choice needs a benchmark, not a hunch.

Run it & wire it in

This was an internal tool: the steps are real, but running it needs access to the system it targets (your tracker, the app’s API, the designs). Treat it as a faithful how-it-ran guide.

Before you start

  • Node >= 18 and a terminal (macOS/Linux shell or Windows PowerShell).
  • The assistant API's base URL and access token, so the agent can issue real prompts.
  • A golden dataset JSON — the file The Answer Grader's convert step emits, or any dataset in that shape.
  • The toolkit's local scoring service running, so each response gets a privacy/safety and quality check.
  • (Optional) GOOGLE_API_KEY and/or ANTHROPIC_API_KEY to enable Gemini and Claude as external benchmarks.

Step by step

  1. Install Node.js — the runtime for the agent.
    # macOS (with Homebrew):
brew install node

# or download the LTS installer from nodejs.org, then check it worked:
node -v   # should print v18 or higher
    Why The agent is a TypeScript program executed by Node. One-time install per machine.
    First run Needed only the first time on a new machine.
  2. Clone the agent code, install dependencies, and start the local scoring service.
    cd path/to/the-agents
npm install

# one-time: install the scoring service's own dependencies
npm run eval:service:install

# then start it (leave this running in its own terminal tab)
npm run eval:service:start
    Why npm install pulls the xlsx writer and the model clients. The scoring service is a separate process that runs the privacy/safety and quality checks — it must be listening before a comparison runs.
    First run Installs everything and starts the service listening locally.
    Re-run Leave the service up across comparisons — no restart needed per run.
  3. Point it at the assistant and, optionally, enable external benchmarks (env vars).
    export APP_API_URL=https://your-assistant-host.example.com
export APP_API_TOKEN=your-access-token
export APP_MODEL=gpt4o
export GOOGLE_API_KEY=your-gemini-key       # optional — enables Gemini as a benchmark
export ANTHROPIC_API_KEY=your-claude-key    # optional — enables Claude as a benchmark
    Why Read at startup: which assistant to call, the token that authorizes it, and which external providers are available. Nothing is hard-coded — swap these to retarget environments.
  4. Run a --limit 5 smoke test, then the full comparison.
    # quick check — 5 questions, no outside brains, to confirm the pipeline works
npm run eval:compare -- --limit 5

# full run — the assistant's own brains plus Gemini and Claude as benchmarks
npm run eval:compare -- --include-external
    Why The limited run verifies the wiring — dataset found, assistant reachable, scoring service up — before spending time and API cost on the full set. --include-external adds Gemini and Claude to the matrix.
    First run Runs the full prompt matrix, dual-scores each response, and ranks the models.
    Re-run Every run is independent — nothing carries over. Re-run any time you need a current scoreboard, e.g. after a model upgrade.
  5. Open the scoreboard.
    open outputs/eval/comparisons/model-comparison-<timestamp>.xlsx
# and the same data as JSON, for feeding into another tool:
open outputs/eval/comparisons/model-comparison-<timestamp>.json
    Why The .xlsx is the shareable artifact — Model Summary, per-prompt comparison, raw scores, and a latency sheet. The .json is the same data for programmatic consumption.

What you give it

--models <list>
Comma-separated in-house model ids to include (default: the standard gpt4o/gpt4omini pair).
--include-external
Adds enabled external models (Gemini, and Claude when requested by id) as benchmarks.
--limit <n>
Run only the first N prompts — a smoke test.
--dataset <path>
Which golden dataset to use; without it, the agent auto-selects the most recently generated one.

What comes back

model-comparison-<timestamp>.xlsx
A multi-sheet scoreboard — model summary, per-prompt comparison, raw dimension scores, and latencies.
model-comparison-<timestamp>.json
The same comparison, machine-readable.
model-comparison-<timestamp>.docx (optional)
A cover-page report naming the winner, for sharing outside the team.
Running it again. No incremental mode — every run is a fresh, timestamped comparison. Re-run whenever you need a current scoreboard, e.g. right after a model upgrade or when a new external model becomes available.
Plug it into your stack. The winner and recommendation are the evidence for choosing the backing model. Wire a nightly --limit 5 --include-external run into CI as a lightweight regression check that the chosen model hasn't silently degraded.

Under the hood — for the curious

A slide for each moving part. Slide back and forth.

1 / 6

Resolves the model set

When it runs
First, before any prompt is sent.
Takes in
Requested model ids, plus the --include-external flag.
Shows out
A validated ModelDef[] of at least two models — in-house registry entries plus enabled external ones (Gemini, Claude) when requested.
2 / 6

Runs the prompt matrix

When it runs
Once per prompt, per model.
Takes in
One shared prompt from the dataset.
Shows out
Response text and latency from each model, via the in-house app client or the external provider APIs.
3 / 6

Dual-scores each response

When it runs
Immediately after each response returns.
Takes in
The prompt and the response.
Shows out
A privacy/safety gate result from the checker service, plus a 1-10 six-dimension rubric score from the LLM-as-judge.
4 / 6

Combines into a verdict

When it runs
Once both scores exist.
Takes in
The gate result and the six rubric scores.
Shows out
One aggregate score and a PASS / WARNING / FAIL verdict for that response.
5 / 6

Aggregates the scoreboard

When it runs
After the full matrix completes.
Takes in
Every scored response across all models.
Shows out
Per-model means, a ranking, and a gap-calibrated recommendation naming the winner.
6 / 6

Writes the artifacts

When it runs
Last, once the scoreboard is final.
Takes in
The finished comparison.
Shows out
A multi-sheet .xlsx, a .json data file, and an optional .docx cover report.
