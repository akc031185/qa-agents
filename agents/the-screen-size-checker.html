Checking the screens look right

The Screen-Size Checker

Captures every screen at nine viewport profiles via Playwright device emulation and reports capture coverage as a pass/fail grid plus a single percentage.

Source file: responsive-testing-agent.ts

Emulates nine viewport profiles — a 1920×1080 desktop plus four phones in portrait and landscape — captures each mapped screen at each, then checks the captures dir for the expected PNG per screen-per-viewport. Output is a grid (screens × viewports) with a mark where a capture exists and a dash where it's missing, plus an overall coverage percentage. A missing cell means the screen failed to render at that viewport.

Why this exists

The chore it removes

By hand: open the browser device toolbar, pick a profile, reload, navigate to a screen, screenshot, repeat per profile and per screen. Nine profiles × dozens of screens is hundreds of manual captures — tedious, slow, and non-deterministic across testers.

→
What you get instead

One run captures every screen at every viewport and emits a coverage grid — mark where the capture landed, dash where it didn't — with total coverage as a single percentage.

A dash in the grid is an early signal that a screen breaks at that viewport — caught before a user on that exact device hits it.

Run it & wire it in

This was an internal tool: the steps are real, but running it needs access to the system it targets (your tracker, the app’s API, the designs). Treat it as a faithful how-it-ran guide.

Before you start

  • Node ≥ 18 and a terminal (macOS/Linux shell or Windows PowerShell).
  • The target app running at a reachable URL (dev or QA) — the agent captures it live at each viewport.
  • ~10 min on first run: npx playwright install downloads the Chromium and WebKit engines before any capture.
  • The screen list and per-screen navigation already wired into the agent (no per-run setup for this part).

Step by step

  1. Install Node.js — the runtime for the agent.
    # macOS (with Homebrew):
brew install node

# or download the LTS installer from nodejs.org, then check it worked:
node -v   # should print v18 or higher
    Why The agent is a TypeScript program executed by Node. One-time install per machine.
    First run Only needed once per new machine.
  2. Install dependencies — once for the agent, once for the Playwright package it drives.
    cd path/to/the-agents
npm install

cd Playwright
npm install
npx playwright install   # downloads the actual Chromium + WebKit browser engines
    Why The agent lives in the project root; the capture layer lives in a sibling Playwright dir with its own deps. npx playwright install fetches the engines — Chromium for desktop/Android, WebKit for iPhone — not bundled with the npm package.
    First run Downloads deps plus the browser engines — the slow part (5-10 min).
    Re-run No-op once installed, unless a dependency or browser version changed.
  3. Set the target URL.
    export APP_URL=https://your-app-url/home
    Why APP_URL is the live app opened at each viewport. Unset, it falls back to a built-in default that won't be your app.
  4. Run it.
    npm run responsive:test -- --word
    Why The full run: captures every mapped screen at nine viewports (desktop + four phones, portrait and landscape) and writes the coverage grid. --word additionally emits a .docx with the captures embedded.
    First run Captures every screen at every viewport from scratch.
    Re-run --capture-only refreshes captures only; --report-only rebuilds the grid from on-disk captures without re-capturing.
  5. Open the generated report.
    open outputs/mobile/reports/responsive-report-<timestamp>.md
    Why The .md holds the coverage grid — Y per captured screen × viewport cell, - per gap — plus the explicit missing-captures list.

What you give it

APP_URL (environment variable)
URL of the running app to capture.
--screens <list>
Comma-separated screen ids to scope the run to a subset instead of the full set.
--landscape, --capture-only, --report-only, --headed, --word
Flags to add landscape viewports, split capture/report phases, run headed (visible browser), or emit a .docx.

What comes back

responsive-report-<timestamp>.json / .md
Machine-readable and rendered coverage grid plus the overall percentage.
responsive-report-<timestamp>.docx (optional)
.docx with the captures embedded; emitted only with --word.
outputs/mobile/captures/*.png
Raw captures, one per screen per viewport — reused by --report-only on a later run.
Running it again. --report-only skips capture and rebuilds the grid from existing captures — useful to re-derive the numbers without a re-capture. A flagless run always re-captures every screen at every viewport, since coverage shifts with every build.
Plug it into your stack. Run the nine-viewport sweep as a pre-release build gate; a dropping coverage percentage, or a screen gaining a new - in the grid, is a regression worth blocking on.
