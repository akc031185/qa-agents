Investigating the app's data & behavior

The App Interviewer

Turns one plain-English request into the correct sequence of API calls, chains their outputs, and executes them against the live app.

Source file: app-api-agent.ts

The app exposes an HTTP API — create_conversation, search_users, list_documents, and so on. This agent lets you drive it in natural language: describe the outcome, and an LLM plans the ordered list of endpoint calls, wires each step's response into the next, executes them with a bearer token, and reports every step's result.

Why this exists

The chore it removes

Driving the API by hand means knowing each endpoint's exact name, its request body shape, and how to feed one call's response into the next. A single wish like 'create a conversation about X and share it with Jordan' is three separate, carefully chained requests. Testers and analysts who aren't developers can't build them by hand.

→
What you get instead

Write one sentence. The agent has an LLM plan the call sequence, threads each step's output into the next via $prev references, executes them against the live API, and logs what each returned.

It turns a developer-only API into something anyone on the team can drive with a sentence, so testing and everyday tasks stop bottlenecking on scarce technical hands.

See it in action

Run it & wire it in

This was an internal tool: the steps are real, but running it needs access to the system it targets (your tracker, the app’s API, the designs). Treat it as a faithful how-it-ran guide.

Before you start

  • Node ≥ 18 and a terminal (macOS/Linux shell or Windows PowerShell).
  • A reachable instance of the app's API to target, plus a bearer token authorized to call it.
  • Directory search must be reachable through that same API, since any share-with-a-named-person step resolves people by name.
  • An AI key (defaults to a Google model) — a sentence has to be planned into an ordered call sequence before anything executes.

Step by step

  1. Install Node.js — the runtime the agent runs on.
    # macOS (with Homebrew):
brew install node

# or download the LTS installer from nodejs.org, then check it worked:
node -v   # should print v18 or higher
    Why The agent is a TypeScript program; Node executes it. Install once per machine.
    First run Only needed on a fresh machine.
  2. Clone the agent code and install its dependencies.
    cd path/to/the-agents
npm install
    Why npm install pulls the agent's dependencies — the AI client and the HTTPS request helper it calls the API with.
    First run Downloads everything (a minute or two).
    Re-run No-op once installed, unless the dependency list changed.
  3. Set the target environment (environment variables).
    export APP_API_URL_DEV=https://dev.your-app.example.com
export APP_API_TOKEN_DEV=your-bearer-token
export GOOGLE_API_KEY=your-ai-key
export APP_MODEL=gpt5   # optional, this is the default
    Why The base URL and token select the environment's API and authorize it. The AI key is what plans your one-sentence request into an ordered call sequence.
  4. State the outcome in one sentence and run it.
    npx ts-node agents/app-api-agent.ts --env dev \
  --prompt "Create a conversation asking about renewable-energy projects and share it with Rivera, Sam"
    Why --env selects the environment; --prompt is your sentence. The agent plans it (create, then ask, then share), resolves 'Rivera, Sam' against the directory, and executes every step against the live API.
    First run Nothing is cached — it plans and executes live against the real environment every time.
    Re-run Identical each time: a brand-new conversation is created and, if sharing was requested, a fresh share call goes out.
  5. Open the run record.
    open ./outputs/reports/api-agent/ApiAgent_dev_<timestamp>.json
    Why The saved file holds the LLM's step-by-step plan plus the raw response from every step — proof of exactly what ran, in what order.

What you give it

--env dev|qa
Which environment's API to call.
--prompt "..."
One natural-language sentence describing the outcome you want.
environment variables
The API URL and bearer token for the chosen environment, plus the AI key.

What comes back

console log
Each step in the plan printed as it runs, with a one-line result summary.
ApiAgent_<env>_<timestamp>.json
The full plan the LLM produced plus every step's raw response, timestamped for the record.
Running it again. No idempotency: running the same prompt twice creates two conversations, and if the prompt includes a share step, fires the share twice. Treat every run as a fresh, live action against the real environment, not a safe replay.
Plug it into your stack. The fastest way to smoke-test the API after a deploy — one sentence exercises a whole chain of real calls (create, ask, share) instead of three hand-built requests. Feed it a prompt list from a CI job to catch a broken chain before a person does.
