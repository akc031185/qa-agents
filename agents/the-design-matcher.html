Checking the screens look right

The Design Matcher

Diffs Figma reference exports against live-app screenshots captured across desktop and phone viewports, and flags every screen that's missing, partial, or unreachable on mobile.

Source file: design-comparison-agent.ts

Pairs each screen's Figma export with a Playwright-captured screenshot of the running app at every configured viewport, classifies each as MATCH / PARTIAL / NOT_IMPLEMENTED by counting which viewports actually produced a capture, and emits a side-by-side report. The key signal: a feature that renders on desktop but has no mobile capture surfaces as a PARTIAL (desktop-only) with a per-device reason.

Why this exists

The chore it removes

The manual path: open the app, resize to each phone viewport, navigate to every screen, screenshot it, open the matching Figma export, and eyeball the pair — across dozens of screens and multiple viewports. Slow, error-prone to track, and non-deterministic between reviewers.

→
What you get instead

One command drives a headless browser through every screen at every viewport, captures each, pairs it with its Figma reference, and classifies the gap deterministically — same navigation, same viewports, same output every run.

A feature that renders on desktop but is unreachable on mobile is a dead end for phone users. Counting captures per viewport catches that before it ships.

What this step does

See it in action

Run it & wire it in

This was an internal tool: the steps are real, but running it needs access to the system it targets (your tracker, the app’s API, the designs). Treat it as a faithful how-it-ran guide.

Before you start

  • Node ≥ 18 and a terminal (macOS/Linux shell or Windows PowerShell).
  • The target app running at a reachable URL (dev or QA) — the agent captures it live, not from a mockup.
  • A local dir of Figma-exported PNGs, one per mapped screen, filenames matching the screen ids.
  • ~10-15 min on first run: npx playwright install downloads the Chromium and WebKit engines before any capture.

Step by step

  1. Install Node.js — the runtime for the agent.
    # macOS (with Homebrew):
brew install node

# or download the LTS installer from nodejs.org, then check it worked:
node -v   # should print v18 or higher
    Why The agent is a TypeScript program executed by Node. One-time install per machine.
    First run Only needed once per new machine.
  2. Install dependencies — once for the agent, once for the Playwright package it drives.
    cd path/to/the-agents
npm install

cd Playwright
npm install
npx playwright install   # downloads the actual Chromium + WebKit browser engines
    Why The agent lives in the project root; the browser-driving layer lives in a sibling Playwright dir with its own deps. npx playwright install fetches the Chromium + WebKit engines — they aren't bundled with the npm package.
    First run Downloads deps plus the browser engines — the slow part (5-10 min).
    Re-run No-op once installed, unless a dependency or browser version changed.
  3. Set the target URL and drop in the Figma exports.
    export APP_URL=https://your-app-url/home

# copy the designer's exported PNGs into inputs/mobile/pages/,
# named to match each screen the agent knows about
    Why APP_URL is the live app the capture spec navigates; unset, it falls back to a built-in default that won't be your app. The PNGs are the reference half of each diff — a screen with no export renders its live capture with nothing to compare against.
  4. Run it.
    npm run design:compare -- --word
    Why The full run: captures every mapped screen at every viewport (desktop + phones), pairs each with its Figma reference, classifies the gap, and writes the report. --word additionally emits a .docx with images embedded side by side.
    First run Navigates and captures every screen at every viewport from scratch — the ~10 min part.
    Re-run --report-only rebuilds the report from on-disk captures without re-capturing; --capture-only does the inverse (refresh captures, skip the report).
  5. Open the generated report.
    open outputs/mobile/reports/design-comparison-<timestamp>.md
    Why The .md is the side-by-side diff — Figma reference next to the live capture at each viewport, each screen labeled MATCH, PARTIAL, or NOT_IMPLEMENTED.

What you give it

APP_URL (environment variable)
URL of the running app to capture.
inputs/mobile/pages/*.png
Figma-exported reference PNGs, one per mapped screen, filenames matching screen ids.
--screens <list>, --landscape, --capture-only, --report-only, --word
Flags to filter screens, add landscape viewports, split capture/report phases, or emit a .docx.

What comes back

design-comparison-<timestamp>.json / .md
Machine-readable and rendered report — per-screen status and observations.
design-comparison-<timestamp>.docx (optional)
.docx with the Figma reference and every viewport's capture embedded side by side; emitted only with --word.
outputs/mobile/captures/*.png
Raw captures, one per screen per viewport — reused by --report-only on a later run.
Running it again. --report-only skips capture entirely and rebuilds the report from whatever is in the captures dir — useful when only the Figma references changed. A flagless run always re-captures, since there's no content-hash/fingerprint of the live app the way document-based agents fingerprint their inputs.
Plug it into your stack. Wire the full run into a nightly or pre-release CI job so every merge gets a fresh diff. Treat any screen that flips MATCH → PARTIAL or NOT_IMPLEMENTED as a regression to triage before ship.

Pairing capture to reference per viewport

When it runs
After both captures and references are resolved.
Takes in
Every capture filename plus the copied reference map.
Shows out
A per-screen match record listing which viewports produced a capture.

Classifying the gap

When it runs
Immediately after pairing.
Takes in
Each screen's per-viewport match record.
Shows out
A MATCH / PARTIAL / NOT_IMPLEMENTED label plus a per-device reason for each missing viewport (e.g. buried in a swipeable row, desktop-sidebar-only).
5 / 5

Emitting the report

When it runs
Last, after all screens are classified.
Takes in
The full classified ScreenComparison[].
Shows out
A JSON report and a Markdown report, plus — with --word — a .docx with reference and every viewport's capture embedded side by side.
