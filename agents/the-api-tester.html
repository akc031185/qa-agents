The API Tester

One typed REST client that probes a live service, retries transient failures, and captures request/response evidence on every call.

Source file: src/core/api.ts

A single ApiClient any agent uses to call a live HTTP service and capture proof of exactly what was sent and returned. It attaches auth headers from config, retries transient failures with backoff instead of throwing, and normalizes every response into an EvidenceStep the report builder renders. It replaces ~96 check scripts that each re-implemented the same fetch, auth, retry, and evidence plumbing.

Why this exists

The chore it removes

The prior setup had ~96 check scripts, each re-implementing the same request plumbing: how to call, how to attach the bearer/subscription header, what to do on a network hiccup, and how to record the result. Repetitive, subtly error-prone, and a single transient failure could crash a whole run.

→
What you get instead

One client built from an ApiConfig. It attaches Authorization: Bearer and Ocp-Apim-Subscription-Key for you, retries on transient failure with linear backoff (default 4 attempts) instead of throwing, and stamps every call into an EvidenceStep carrying the exact request and response. Assertion helpers — expectStatus, expectJsonPath — turn a response into a typed pass/fail. Nothing is tied to a specific service.

When a service misbehaves, the captured EvidenceStep shows the exact request, status, and response body side by side — a provable finding, not a vague 'it's broken'. And a flaky network degrades to a clean code: 0 result instead of crashing the suite.

See it in action

Run it & wire it in

You can run this yourself, end to end — every command below is real.

Before you start

  • Node ≥ 18 and a terminal (macOS/Linux shell or Windows PowerShell).
  • Node.js (installed in step 1 below) — nothing else.
  • No credentials, board, database, or API key are needed for the demo below — that is the point of this module. A .env only matters later, if you point it at something real.

Step by step

  1. Install Node.js — the runtime.
    # macOS (with Homebrew):
brew install node

# or download the LTS installer from nodejs.org, then check it worked:
node -v   # should print v18 or higher
    Why The toolkit is TypeScript on Node. One install per machine; no other runtime required.
    First run First time on a new machine only.
  2. Clone and install dependencies.
    cd path/to/qa-agent-toolkit
npm install
    Why npm install pulls the toolkit's only dependency (dotenv) into node_modules. No DB driver, no cloud SDK, no auth library — which is why the demos run credential-free.
    First run Downloads everything (seconds — the dependency list is tiny).
    Re-run No-op unless the dependency list changed.
  3. (Optional) copy the env template — only to go live later.
    cp .env.example .env
# then open .env and fill in ONLY the section you need
    Why Skippable for the demo — every capability is off by default and the demo targets a public sandbox regardless. .env matters only once you point the toolkit at a real board, service, or database.
  4. Run the capability check.
    npm run doctor
    Why Prints a one-line scorecard per capability (tracker, API, database, AI) — on/off with a reason. With an empty .env everything reads (off), which is expected: the demo sets its own target in-code.
  5. Run the API demo — probe a public, no-auth test service.
    npm run demo:api
    Why Points the real ApiClient at a public credential-free API (jsonplaceholder.typicode.com) and runs two probes — a GET and a POST — each with several expectStatus / expectJsonPath checks. Real client, retries and evidence capture included; only the target is a public sandbox.
    First run Makes two real HTTP calls and prints an EvidenceStep per check.
    Re-run The GET is idempotent (same todo, same answer). The POST hits jsonplaceholder's sandbox, which never actually persists — so reruns are equally safe and the same checks pass.
  6. Read the evidence.
    # printed straight to the terminal — no file written:
#   ✓ [pass] Todo endpoint returns 200
#   ✓ [pass] Response carries the requested id
#   ...
#   Evidence summary: 8 steps, 6 pass, 0 fail, overall PASS.
    Why Each check prints the exact request sent, the status, and the response — that receipt is the point: a mismatch shows real-vs-expected side by side instead of a vague 'it failed'.

What you give it

nothing
The demo constructs its own ApiConfig in-code pointing at a public API (jsonplaceholder.typicode.com) — no .env, token, or subscription key. If the network is unreachable it degrades gracefully and says so rather than crashing.
API_BASE_URL / API_BEARER_TOKEN / API_SUBSCRIPTION_KEY (optional)
Set these in .env to point the same ApiClient + probe helpers at your own live service instead.

What comes back

console evidence log
One block per probe step: what it did, the exact request (method + URL), the status, and a trimmed response body, followed by a pass/fail verdict per check.
summary line
'Evidence summary: 8 steps, 6 pass, 0 fail, overall PASS.' — or a graceful 'network unavailable — client wiring verified' if the machine has no internet.
Running it again. Safe to rerun freely: the GET is a read against a fixed public record, and the POST hits a sandbox that never stores what you send — jsonplaceholder just echoes back a fake id. Point the same client at a real API and reruns reflect that service's current state.
Plug it into your stack. Import directly: import { ApiClient } from './src/core/api', construct it with your own ApiConfig (baseUrl, bearerToken, subscriptionKey), and write probes with runApiProbes() (./agents/api) using ctx.step() / ctx.expectStatus() / ctx.expectJsonPath() exactly as examples/api/demo.ts does — every probe returns a normal AgentResult with evidence steps, ready to feed straight into the report builder.
