The Share Tester

Exercises the create-answer-share flow end to end via API: creates a conversation, sends a prompt, then shares it with the exact recipients you name — repeatably, in batch.

Source file: conversation-share-agent.ts

Drives the app's ask-then-share path through its HTTP API. For each prompt it POSTs a new conversation, sends the prompt, reads the assistant's answer, then shares that conversation with the recipients you list — read-only or edit. Runs a whole prompt batch in one invocation.

Why this exists

The chore it removes

Testing sharing by hand means: open the app, start a conversation, type a prompt, wait for the answer, open the share panel, search each recipient by name, pick the right person out of the directory, set their permission, confirm — then repeat for every prompt and every recipient. Slow, and easy to share with the wrong 'John' or skip a step.

→
What you get instead

Give it a prompt list and a name list once. It creates and shares every conversation, resolves each recipient against the directory (exact match, fuzzy fallback), records who it shared with and whether the call succeeded, and returns a clean summary with every conversation ID.

Sharing puts one person's work in someone else's hands — quietly sharing with the wrong person, or failing to share at all, is exactly the bug you want caught before real users hit it.

What this step does

See it in action

Run it & wire it in

This was an internal tool: the steps are real, but running it needs access to the system it targets (your tracker, the app’s API, the designs). Treat it as a faithful how-it-ran guide.

Before you start

  • Node ≥ 18 and a terminal (macOS/Linux shell or Windows PowerShell).
  • A reachable instance of the app's API for the target environment, plus a bearer token for it.
  • Directory search must be reachable through that same API, since every recipient is resolved by exact name.
  • (Optional) a plain text file of prompts, one per line, to run a batch instead of a single prompt.

Step by step

  1. Install Node.js — the runtime the agent runs on.
    # macOS (with Homebrew):
brew install node

# or download the LTS installer from nodejs.org, then check it worked:
node -v   # should print v18 or higher
    Why The agent is a TypeScript program; Node executes it. Install once per machine.
    First run Only needed on a fresh machine.
  2. Clone the agent code and install its dependencies.
    cd path/to/the-agents
npm install
    Why npm install pulls the agent's dependencies — the API client and the env-config loader — into node_modules.
    First run Downloads everything (a minute or two).
    Re-run No-op once installed, unless the dependency list changed.
  3. Set the target environment (environment variables).
    export APP_API_URL_DEV=https://dev.your-app.example.com
export APP_API_TOKEN_DEV=your-bearer-token
export APP_MODEL=gpt5   # optional, this is the default
    Why The URL and token select the environment's API and authorize it. Swap them and the identical run targets a different environment.
  4. Run a prompt and a recipient.
    npx ts-node agents/conversation-share-agent.ts \
  --env dev \
  --prompt "Summarize our aviation portfolio" \
  --share-with "Okafor, Ada" \
  --role read-only

# batch mode, reading prompts from a file:
npx ts-node agents/conversation-share-agent.ts \
  --env dev --input prompts.txt --share-with "Okafor, Ada"
    Why Per prompt it creates a conversation, sends the prompt, reads the full answer, then shares with every resolved recipient at the chosen role.
    First run Resolves every recipient against the directory first, then runs the create-answer-share sequence for every prompt.
    Re-run Identical sequence again — new conversations are created and shared each time, nothing is skipped or deduplicated.
  5. Open the report.
    open ./outputs/reports/conversation-shares/ConvShare_dev_<timestamp>.json
    Why Lists every conversation created, its full answer, and each recipient's share outcome — the permanent record of the run.

What you give it

--prompt "..." (repeatable) or --input <file>
One or more prompts to send, typed directly or read one-per-line from a text file.
--share-with "Last, First" (repeatable)
The exact display name of each recipient to share with.
--role read-only|edit
The permission level to share at (defaults to read-only).
--env, environment variables
Which environment to target, plus the URL and token that authorize it.

What comes back

console log
Per prompt: the conversation created, the answer's word count, and each share's success or failure.
ConvShare_<env>_<timestamp>.json
Every conversation ID, its full answer, and each recipient's share outcome, timestamped for the record.
Running it again. Not idempotent — each run creates new conversations and re-fires share requests; running the same command twice doubles the conversations. That makes it well suited to a repeated regression sweep, not a one-time share you only want to happen once.
Plug it into your stack. Drop it into a nightly regression job with a fixed prompt list and a couple of test-account names — it becomes a standing check that the create-answer-share chain still works end to end, and the saved conversation IDs give you a paper trail to open by hand if something looks off.
