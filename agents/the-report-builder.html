The Report Builder

Turns any agent's AgentResult[] into a single self-contained HTML report — inlined CSS, light/dark, no external assets.

Source file: src/core/html.ts

One shared renderer that takes the AgentResult[] from any agent — tracker, API, DB — and emits a self-contained HTML report: stat tiles, a results table, colour-coded pass/fail badges, an evidence panel per agent, and an optional run matrix. It replaces ~90 report scripts that each hand-rolled their own layout, colours, and markup. Every page now draws from one CSS token set, so a single edit re-skins them all.

Why this exists

The chore it removes

The prior setup had ~90 report scripts, each hand-writing its own page layout, colour hexes, tables, and status labels. They drifted, so reports looked inconsistent, and changing the look meant editing every script.

→
What you get instead

One kit of typed helpers — statCards, table, badge, evidenceSteps, runMatrix — all reading from a single THEME_CSS token set. Every report is byte-for-byte consistent, re-skinnable from one place, and emitted as a single standalone HTML file: CSS inlined, no external stylesheet, no network — trivial to email, archive, or screen-record.

One renderer, one token set: consistent reports produced in milliseconds instead of hand-built per project. Feed it any agent's AgentResult[] and it composes into the same dashboard — self-contained HTML that opens anywhere, offline, unchanged years later.

Run it & wire it in

You can run this yourself, end to end — every command below is real.

Before you start

  • Node ≥ 18 and a terminal (macOS/Linux shell or Windows PowerShell).
  • Node.js (installed in step 1 below) — nothing else.
  • No credentials, board, database, or API key are needed for the demo below — that is the point of this module. A .env only matters later, if you point it at something real.

Step by step

  1. Install Node.js — the runtime.
    # macOS (with Homebrew):
brew install node

# or download the LTS installer from nodejs.org, then check it worked:
node -v   # should print v18 or higher
    Why The toolkit is TypeScript on Node. One install per machine; no other runtime required.
    First run First time on a new machine only.
  2. Clone and install dependencies.
    cd path/to/qa-agent-toolkit
npm install
    Why npm install pulls the toolkit's only dependency (dotenv) into node_modules. No DB driver, no cloud SDK, no auth library — which is why the demos run credential-free.
    First run Downloads everything (seconds — the dependency list is tiny).
    Re-run No-op unless the dependency list changed.
  3. (Optional) copy the env template — only to go live later.
    cp .env.example .env
# then open .env and fill in ONLY the section you need
    Why Skippable for the demo — every capability is off by default and the demo runs on inline sample data regardless. .env matters only once you point the toolkit at a real board, service, or database.
  4. Run the capability check.
    npm run doctor
    Why Prints a one-line scorecard per capability (tracker, API, database, AI) — on/off with a reason. With an empty .env everything reads (off), which is expected: the demo needs none of them on.
  5. Run the report demo — build a self-contained HTML dashboard.
    npm run demo:report
    Why Feeds three synthetic AgentResults (an API probe, a DB reconciliation, an ADO sync) plus a small pass/fail matrix into runReportAgent(), writing the page to out/report/demo-dashboard.html.
    First run Creates out/report/ if missing, then writes demo-dashboard.html.
    Re-run Overwrites the same file with byte-identical content — the demo pins generatedAt to a fixed string, so reruns are deterministic and diff-clean.
  6. Open the dashboard.
    open out/report/demo-dashboard.html
    Why One self-contained HTML file — no server, no network, no external stylesheet — opens in any browser and renders correctly indefinitely. You'll see the stat tiles, colour-coded results table, evidence panels, and pass/fail matrix.

What you give it

nothing
The demo builds its ReportInput entirely inline (examples/report/demo.ts) — three synthetic AgentResults and a 4-row pass/fail matrix. No credentials or files.
a real ReportInput (for your own use)
In a real project you pass the AgentResult[] your own tracker/API/DB agents already returned — same shape, same builder.

What comes back

out/report/demo-dashboard.html
One self-contained HTML page: stat tiles ('3 Agents · 2 Passed · 1 Failed'), a colour-coded results table, an evidence panel per agent, and the 4×3 pass/fail matrix — all inlined, nothing external to load.
Running it again. Deterministic and safe to rerun: the file is fully overwritten each run, and because the demo pins generatedAt, the output bytes are identical run to run. Point runReportAgent() at real AgentResults and every rerun simply reflects your latest test results.
Plug it into your stack. Import directly: import { runReportAgent } from './agents/report', hand it a ReportInput ({ title, subtitle, results, matrix, generatedAt }) built from your agents' AgentResults plus an output path — it returns its own AgentResult pointing at the file, so a report step composes with every other agent. For custom pieces, import the lower-level helpers (statCards, table, badge, evidenceSteps, THEME_CSS) straight from ./src/core/html.
