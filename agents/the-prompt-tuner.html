Grading the AI assistant's answers

The Prompt Tuner

A/B-tests draft system prompts over a shared prompt set and scores which one makes responses shorter, more on-point, and less pushy.

Source file: response-optimization-agent.ts

The same assistant reads as rambling or crisp depending on its system prompt. This agent runs one fixed prompt set through several draft system prompts, scores each on a six-dimension rubric — length, relevance, follow-up quality, tone, and more — and ranks them against a no-prompt baseline. The baseline is the starting line every draft is measured against.

Why this exists

The chore it removes

Tuning how an assistant talks is normally guesswork: tweak the instructions, eyeball a few replies, form a gut feeling. There's no consistent way to tell whether a new draft actually shortened responses, held relevance, cut the pushy 'would you like me to...' follow-ups, or warmed the tone — and no way to prove the change helped rather than regressed.

→
What you get instead

Every draft is scored on the same rubric — word count, relevance, follow-up quality, tone, and more — against the no-prompt baseline, with a named winner and the exact per-dimension delta each draft moved.

Shorter, sharper, less pushy responses are the difference between an assistant people reach for and one they find exhausting.

See it in action

Run it & wire it in

This was an internal tool: the steps are real, but running it needs access to the system it targets (your tracker, the app’s API, the designs). Treat it as a faithful how-it-ran guide.

Before you start

  • Node >= 18 and a terminal (macOS/Linux shell or Windows PowerShell).
  • A spreadsheet of conversation prompts — a prompt column, and ideally target-response-size and follow-up-expectation columns.
  • One or more draft system prompts saved as .txt files — the instruction variants you want to A/B-test.
  • The assistant API's base URL and access token.
  • The toolkit's local checker service running, for the privacy/safety half of the scoring.

Step by step

  1. Install Node.js — the runtime for the agent.
    # macOS (with Homebrew):
brew install node

# or download the LTS installer from nodejs.org, then check it worked:
node -v   # should print v18 or higher
    Why The agent is a TypeScript program executed by Node. One-time install per machine.
    First run Needed only the first time on a new machine.
  2. Clone the agent code, install dependencies, and start the local checker service.
    cd path/to/the-agents
npm install

# one-time: install the checker service's own dependencies
npm run eval:service:install

# then start it (leave this running in its own terminal tab)
npm run eval:service:start
    Why npm install pulls the xlsx reader, the report writers, and the assistant client. The checker service runs the privacy/safety half of scoring — it must be up before evaluating.
    First run Installs everything and starts the service listening locally.
    Re-run Leave the service up across tuning runs — no restart per run.
  3. Point it at the assistant (env vars).
    export APP_API_URL=https://your-assistant-host.example.com
export APP_API_TOKEN=your-access-token
export APP_MODEL=gpt4o
    Why Read at startup: which assistant to query and the token that authorizes it. Nothing is hard-coded — swap these to retarget environments.
  4. Convert the spreadsheet into a prompt bank, then measure the no-prompt baseline.
    npm run opt:convert -- --input path/to/conversation-questions.xlsx
npm run opt:baseline
    Why opt:convert builds the prompt bank the run consumes. opt:baseline runs every prompt with no draft attached — the vanilla behavior every draft is measured against.
    First run Parses the spreadsheet, then queries every prompt with no system prompt attached and scores each reply.
    Re-run Re-measure the baseline whenever the underlying assistant itself changes, so the comparison point stays honest.
  5. Run one draft, or bake several off against each other.
    # one draft
npm run opt:run -- --system-prompt inputs/system-prompts/draft-v1.txt --sp-label v1

# several drafts, bake-off style
npm run opt:compare -- --system-prompts draft-v1.txt,draft-v2.txt
    Why Each draft is prepended to every prompt before sending (the platform doesn't allow swapping the real system prompt — noted in the run so results are read correctly). opt:compare runs several drafts back to back and ranks them.
    First run Runs the whole prompt bank once per draft and scores every reply on six dimensions.
    Re-run Safe to re-run after tweaking a draft — each run gets its own labeled, timestamped report.
  6. Open the comparison.
    open outputs/response-opt/opt-run-<label>-<timestamp>.xlsx
# a short plain-text summary anyone can paste into chat:
open outputs/response-opt/opt-run-<label>-<timestamp>-SHAREABLE.txt
    Why The .xlsx has the full per-draft breakdown — word counts, follow-up counts, and all six dimensions — against baseline. The SHAREABLE.txt is the short form for a ticket or chat.

What you give it

--system-prompt <path>
One draft system prompt (a .txt file) to test.
--sp-label <name>
A short label for that draft, e.g. v1, v2 — shown in every report.
--system-prompts <a,b,c>
Several draft system prompts to bake off against each other and the baseline in one run.
--limit <n>
Run only the first N prompts — a quick check before a full run.

What comes back

opt-run-<label>-<timestamp>.json / .md
The full run for one draft — word counts, follow-up counts, and the six-dimension scores.
opt-run-<label>-<timestamp>.xlsx
A formatted spreadsheet of the same run, color-coded by PASS / WARNING / FAIL.
opt-run-<label>-<timestamp>-SHAREABLE.txt
A short plain-text summary for pasting anywhere.
Running it again. Re-measure the baseline only when the underlying assistant changes; drafts can be re-run freely after every tweak, since each run is independent and separately labeled — nothing is overwritten.
Plug it into your stack. This is how a team picks which draft system prompt ships — the ranked comparison against baseline is the evidence, not a gut feeling. Promote the winning .txt to the new baseline, and re-run the bake-off any time someone proposes another wording change.

Under the hood — for the curious

A slide for each moving part. Slide back and forth.

1 / 6

Parses the prompt bank

When it runs
First, before any draft is tested.
Takes in
A spreadsheet of conversation prompts.
Shows out
A prompt bank carrying each prompt's target response size and follow-up expectation.
2 / 6

Prepends the draft and queries the assistant

When it runs
Once per prompt, per draft (and once with no prompt, for baseline).
Takes in
One prompt, plus the draft system-prompt text (or nothing, for baseline).
Shows out
The assistant's real reply to the combined message.
3 / 6

Checks response length

When it runs
Right after each reply returns.
Takes in
The reply text and the prompt's complexity tier.
Shows out
A word count against the tiered ceiling, flagged ok / warn / fail.
4 / 6

Detects and classifies follow-ups

When it runs
Alongside the length check.
Takes in
The reply text.
Shows out
A follow-up count, each labeled action or question, against the limit of 3.
5 / 6

Scores with an LLM judge

When it runs
After the length and follow-up checks, using them as context.
Takes in
The reply, plus the pre-computed length and follow-up analysis.
Shows out
A 1-10 score on six dimensions: accuracy, relevance, conciseness, hallucination resistance, follow-up quality, tone.
6 / 6

Aggregates and compares

When it runs
Last, once a draft has run over every prompt.
Takes in
Every scored reply for that draft.
Shows out
One summary of per-dimension means and word/follow-up counts — set against baseline and other drafts to name a winner.
